# PPM 数据分析系统 — 技术栈与整体架构

## 一、数据格式说明（与 `ppm` 目录 Excel 一致）

系统需兼容以下三类数据源：

| 数据源 | 主要字段 | 用途 |
|--------|----------|------|
| **供应商 PPM** | PPM月份、供应商编码、供应商名称、月不合格数、月供货量、供应商总PPM；各基地（河西/宝骏/青岛/重庆）的 可疑物料、供货量、供应商PPM | 各基地×供应商 PPM 结果 |
| **可疑物料统计** | 区域工厂、录入日期、零件号、零件名称、供应商名称、供应商代码、数量、可疑物料数量、供货量、失效描述、故障类别等 | 明细数据，用于计算与追溯 |
| **基地供货量**（如重庆供货量） | fiscal_year、supplier_code、supplier_name、part_code、part_name、plant_id、month_x_no 等 | 按基地×供应商×零件 的供货量 |

**PPM 计算公式**：`PPM = (不合格数 / 供货量) × 1,000,000`  
计算维度：**基地 × 供应商**（必要时可扩展至 基地 × 供应商 × 零件）。

## 二、技术栈选型

### 3.2 后端模块划分（单应用架构）

```
ppm-backend/
├── src/main/java/.../ppm/
│   ├── config/         # 配置、安全、CORS、全局异常处理（GlobalExceptionHandler）
│   ├── controller/     # 导入、计算、统计、查询
│   ├── service/        # 业务逻辑
│   ├── repository/     # 数据访问
│   ├── entity/         # 实体
│   ├── dto/            # 请求/响应 DTO（含 Result、PageResult）
│   └── util/           # 工具类
├── src/main/resources/
│   ├── application.yml
│   └── db/migration/   # Flyway 脚本
└── pom.xml
```

**当前实现**：已按上述单应用结构落地，统一响应与分页结果置于 `dto`，全局异常处理置于 `config`。

### 3.3 核心数据表（与 Excel 对应）

| 表名 | 用途 | 主要字段（示例） |
|------|------|------------------|
| `supplier_ppm_summary` | 各基地×供应商 PPM 汇总（计算结果写入） | id, ppm_month, base_id, base_name, supplier_code, supplier_name, defect_count, supply_qty, ppm, created_at |

## 四、接口与前端页面规划（概要）

### 4.1 主要 REST 接口

- `POST /api/import/supplier-ppm`：导入供应商 PPM Excel  
- `POST /api/import/suspicious-material`：导入可疑物料统计 Excel  
- `POST /api/import/supply-volume`：导入基地供货量 Excel  
- `POST /api/ppm/calculate`：触发 PPM 计算（按月份、基地等），结果写入 `supplier_ppm_summary`  
- `GET /api/ppm/summary`：分页查询 PPM 汇总（支持基地、供应商、月份筛选）  
- `GET /api/ppm/statistics`：统计接口（如按基地、按供应商、按月份聚合）  
- `GET /api/ppm/export`：导出 Excel  
- `GET /api/query/suspicious-material`：可疑物料多条件查询  
- `GET /api/query/supply-volume`：供货量多条件查询  

### 4.2 前端页面结构

- **工作台/首页**：关键指标卡片、本月 PPM 趋势概览  
- **数据导入**：多个 Excel 上传入口，格式说明与校验提示  
- **PPM 管理**：计算触发、结果列表、筛选、导出  
- **统计分析**：图表（折线、柱状、饼图）、表格  
- **综合查询**：可疑物料、供货量、PPM 结果等多维度查询

## 六、MySQL 连接 URL 与配置

### 6.1 连接 URL 格式

```
jdbc:mysql://<host>:<port>/<数据库名>?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true&createDatabaseIfNotExist=true&nullCatalogMeansCurrent=true
```

| 参数 | 说明 |
|------|------|
| `host` | MySQL 主机，本地为 `localhost` |
| `port` | 端口，默认 `3306` |
| `数据库名` | 如 `ppm_db`，Flyway 会在此库建表 |
| `useUnicode` / `characterEncoding=utf8` | UTF-8 编码（注意：JDBC 只支持 `utf8`，不支持 `utf8mb4`；数据库和表的字符集已在建表 SQL 中设置为 utf8mb4） |
| `serverTimezone=Asia/Shanghai` | 时区 |
| `useSSL=false` | 本地开发可关 SSL；生产建议 `true` 并配置证书 |
| `allowPublicKeyRetrieval=true` | MySQL 8 认证常见需要 |
| `createDatabaseIfNotExist=true` | 库不存在时自动创建 |
| `nullCatalogMeansCurrent=true` | 避免部分驱动下 catalog 解析问题 |

### 6.2 默认配置与覆盖方式

- **默认**：`application.yml` 中 `url: jdbc:mysql://localhost:3306/ppm_db?...`，`username: root`，`password: root`。
- **本地覆盖**：复制 `application-local.yml.example` 为 `application-local.yml`，修改 `url` / `username` / `password`，启动时加 `--spring.profiles.active=dev,local`。
- **环境变量**：可设置 `SPRING_DATASOURCE_URL`、`SPRING_DATASOURCE_USERNAME`、`SPRING_DATASOURCE_PASSWORD` 覆盖，无需改配置文件。

### 6.3 示例（本地 / 远程）

- 本地：`jdbc:mysql://localhost:3306/ppm_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true&createDatabaseIfNotExist=true&nullCatalogMeansCurrent=true`
- 远程：将 `localhost:3306` 换为实际 `host:port`，按需调整 `useSSL`、`allowPublicKeyRetrieval`。
