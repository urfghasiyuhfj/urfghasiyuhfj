## 四、功能模块测试

### 4.1 综合查询 — 录入时间筛选（已知问题）

**模块**：综合查询 / 可疑物料  
**功能**：按「录入日期」范围筛选  

**代码审查结论**：

| 环节 | 文件 | 状态 | 说明 |
|------|------|------|------|
| 前端参数 | `Query.vue` L148–156 | ⚠️ 待验证 | `const [from, to] = suspForm.recordDateRange \|\| []` 在 `recordDateRange` 为 `null` 时得到 `[undefined, undefined]` |
| 前端 API | `queryApi.js` | ✅ | 使用 `params` 传递，参数名正确 |
| 后端接口 | `QueryController.java` L35–38 | ✅ | `recordDateFrom`、`recordDateTo` 使用 `@DateTimeFormat(iso = ISO.DATE)` |
| 后端逻辑 | `QueryService.java` L43–47 | ✅ | 正确使用 `greaterThanOrEqualTo`、`lessThanOrEqualTo` 过滤 |

**潜在风险**：

1. **日期格式**：`el-date-picker` 使用 `value-format="YYYY-MM-DD"` 时，理论上返回 `YYYY-MM-DD` 字符串；若在某些环境或版本下返回 `Date` 或 ISO 字符串（如 `2024-01-15T00:00:00.000Z`），后端 `ISO.DATE` 可能解析失败。
2. **空值处理**：`recordDateRange` 为 `null` 时，`from`、`to` 为 `undefined`，axios 会省略对应参数，逻辑合理；但仍需在浏览器中验证实际请求 URL 和响应。

**建议**：在前端对日期做统一格式化（如 `toDateStr`），确保始终传递 `YYYY-MM-DD`；并在浏览器 Network 中确认实际请求参数与后端解析结果。
